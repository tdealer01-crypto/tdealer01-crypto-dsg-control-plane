## Overview

The **Design Constitution** is a unified system of 8 integrated design principles (Phases 21–28) that govern every design decision in DSG ONE. It ensures that revenue, sales, and performance components are integrated harmoniously—transparent, trustworthy, and free from manipulation.

This bundle contains everything needed to understand, implement, and evaluate designs against the constitution.

- Green = Proceed; Yellow = Proceed with caution; Red = Revise; Critical = Stop

## How to Evaluate a Design

### Quick Eval (5 minutes)
1. Open `design-review-scorecard.md`
2. Use the **8-Phase Checklist** at the bottom
3. If all 8 are checked ✓: Proceed
4. If any are unchecked: Review the relevant phase

### Full Eval (20 minutes)
1. Answer the **4–5 questions** in each of the 5 sections
2. Score each question (0–5)
3. Calculate section totals
4. Find the overall compliance score (out of 60)
5. Determine status: Green/Yellow/Red/Critical
6. Document and proceed accordingly

### Deep Eval (45+ minutes)
1. Answer all scorecard questions in detail
2. Reference the relevant phase in the full documentation
3. Review the visual exemplar for that phase
4. Discuss with design team if any conflicts
5. Apply the **North Star test** (Phase 28): "Does this build trust through clarity?"
6. Document decision with detailed rationale

## Common Use Cases

### Adding a New Metric (Revenue, Sales, Performance)
**Relevant Phases**: 23 (Living Grid), 26 (Evolution), 28 (North Star)

Checklist:
- [ ] Classify metric: primary/supporting/predictive
- [ ] Assign proportions in grid (61.8% primary, 38.2% supporting)
- [ ] Test scalability: add metric at 3 viewport sizes (mobile, tablet, desktop)
- [ ] Update policy to govern new relationships
- [ ] Document in evolution log
- [ ] Score on design-review-scorecard: target Yellow minimum (36+)

### Redesigning an Approval Workflow
**Relevant Phases**: 21 (Truth), 22 (Ethics), 24 (Interaction), 28 (North Star)

Checklist:
- [ ] Show all 4 elements: decision, policy, evidence, ID
- [ ] Make buttons equal visual weight (no persuasion)
- [ ] Define intent, feedback, and result states
- [ ] Test with 3 users: can they predict outcome?
- [ ] Score minimum 48/100 (Green)

### Updating Error Handling
**Relevant Phases**: 21 (Truth), 22 (Ethics), 24 (Interaction Charter)

Checklist:
- [ ] Specify what went wrong (technical reason)
- [ ] Explain why (policy/system reason)
- [ ] Offer clear next steps (actionable)
- [ ] Blame policy/system, not user
- [ ] Score Phase 24, Question 4 minimum 4/5

### Evolving the Color Palette
**Relevant Phases**: 22 (Visual Ethics), 25 (Identity)

Checklist:
- [ ] Colors reflect semantic meaning (not persuasion)
- [ ] All changes documented in identity guide
- [ ] Team trained before rollout
- [ ] Score Phase 22, Question 1 minimum 4/5

## Questions & Support

**How do I know if my design is Green?**
- Use the scorecard. Score 48+/60 = Green. If unsure on any question, review the phase guidance.

**What if my design scores Yellow?**
- Proceed, but document the tradeoff. Example: "Chose speed (simpler interface) over full transparency (Phase 21). Mitigated by showing evidence in detail view."

**What if two phases conflict?**
- Apply the **North Star test** (Phase 28): "Does this choice build trust through clarity?" That principle resolves the conflict.

**Can I deviate from the constitution?**
- Yes, but document it. Record: Phase, deviations, rationale, and tradeoff. Share with team. Rare exceptions prove the rule.

**Who is responsible for Design Constitution compliance?**
- Designers propose; product/tech lead reviews; design lead approves. Scorecard is your shared tool.
